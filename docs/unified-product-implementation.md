## 已实现的产品边界

- 外壳六页面使用真实 API 和原生模块 iframe，没有生产 srcdoc、演示项目或假计数。项目导入复用生命周期事务，登记双目录、领域和四模块；部分接线失败保留项目，可重试。
- 工作台保留既有流式消息、权限、中止、恢复和模型选择。引擎在发送前检索真实上下文；原生工作台将原始用户输入与成功最终回答可靠投递到唯一 bridge journal，而不是另建对话数据库。
- 供应商与凭据使用工作台配置源；默认维护模型持久化，运行凭据只通过鉴权本地接口下发内存，浏览器反代禁止私有配置接口。
- 引擎执行冻结证据、无头 SDK、staging、严格晋升和索引流程。全局最多两个分析，同项目 FIFO；游标先持久化任务再 ACK；索引失败与晋升失败分开。
- 领域共享知识及已确认记忆与项目文件并存，不移动原知识目录。候选必须有已晋升文件依据，未确认候选不进入任务。
- 外壳托管的 vector-hub 不恢复旧目录监听，只在引擎晋升后更新索引；独立产品仍支持通用监听与管理。
- 原生 Claude 会话恢复已兼容当前工作台项目登记文件。升级不会仅因为缺失旧 projects.json 而漏掉已保存会话。
